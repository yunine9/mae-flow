五条铁律(冲突时以此为准):1 不懈追问直至共同理解;2 沿决策树逐支走,树在对话中生长;
3 每题附推荐答案(含理由与代码佐证);4 一次只问一个,等回答再问下一个;5 事实自己查、决策问用户。
中断恢复:先读 docs/grill-prep-{单号}.md(备课结论)与 docs/clarifications-{单号}.md(已拍板答案),
从未问的题继续——已拍板的禁止重问,文档即状态。
备课(先填工作表,再开口提问):通读 SE 文档 → 定向探索相关模块(禁全库盲探)→
把模板 {GRILL_PREP_TEMPLATE_PATH} 全文复制落盘为 docs/grill-prep-{单号}.md(先保结构后填内容;
章节结构由 hook 按模板校验,缺章会被打回)→ 逐维把「(待填…)」占位替换为结论,8 维禁跳:
每维结论只有两种——已覆盖(附 SE 文档出处;"经查不适用"也归此,写明依据)/ 有缺口(写成候选题,
四要素:缺口位置/代码佐证/推荐答案/实现影响,写不出实现影响的删)。占位残留会被 done 拦截。
第 9 章汇总:候选题按阻塞性排序;技术分歧记入「留给设计阶段」。
高度边界:本阶段只问**需求/规格层**决策(要什么、边界在哪、什么算对);技术实现方案的分歧
(选型、模块划分、算法)不展开、不提问,记入「留给设计阶段」清单(工作表第 9 章,收尾时同步到
clarifications 文档尾部)——那是 comet-design 阶段 brainstorming 的领地,在这里问会和它撞车重复。
质询:按工作表候选题逐题进行,每题一回合,优先 AskUserQuestion(选项=推荐答案(标注"(推荐)"+理由)+主要备选,
用户可 Other 自由输入;工具不可用才结束回复纯文本)。答案即时落盘→结合全部已有答案重审余题→下一题。
收敛:题尽 / 用户说"其余按推荐答案"(落盘标注未经确认)/ 超15题→告知规模由用户选。
落盘:增量写 docs/clarifications-{单号}.md(Phase 1 后移入 change 目录),该文件是 comet-open 输入。
凡属**行为规格**的答案,落盘写成 EARS 句式:「WHEN <条件/触发> THE SYSTEM SHALL <可观测行为>」
(如"WHEN 入参为空列表 THE SYSTEM SHALL 返回空结果并记 INFO 日志")——一句一测,
它是后面 delta spec Scenario 和 UT 验收对照的原材料;写不成 WHEN/SHALL 的答案多半还没问透,回炉再问。
结束展示摘要,等用户确认后 git add docs/ && git commit -m "[单号][类型]需求澄清"(备课工作表一并提交),再 done --ack。
