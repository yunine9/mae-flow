主 Agent 直接读取本单 `spec.md` 与 `story.md`，在本步骤内一次完成需求涉及的全部生产代码：
一次编译、一次人工检视。不要拆开发批次，不要创建额外的编码前计划或实现任务文档。

**设计承载的代码不外包**：接口定义、每类模式的第一个实现、跨模块的接缝，必须主 Agent 亲写——
两个新上下文会各自发明两套方言（两套命名、两个平行 helper），这正是品味问题的主要来源。

**子 Agent 只用于两类工作**（默认不派，满足条件才派）：

- **只读侦察**：需要大量读码时（梳理既有抽象、调用点、模块惯例、可复用实现），派只读子 Agent
  返回精炼结论，把主上下文的注意力留给写码。随时可派，不受数量限制；侦察结论直接服务
  编码基准第 1 条"顺应优先于自包含"。
- **机械扇出**：仅当主 Agent 已亲写第一个完整样例、接口签名已定稿、剩余改动是照样例平移到
  多处（适配调用点、同构的第 N 个实现）。派发时给出精确文件清单 + 样例路径 + 编码基准路径；
  返回后主 Agent 通读其全部改动，按四项自查纳入跨块漂移检查——**子 Agent 的输出不免检**。
  少于三个文件不值得派（冷启动比亲写贵）。

子 Agent 一律禁止 git 操作与提交；派发不改变任何门禁与证据——编译仍然一次、检视仍然一次。

**分块纪律（同一上下文内执行，不产生任何流程动作）**：按 `implementation.md` 已有的任务顺序逐块实现；
每块写完先对照四项自查再写下一块——命名与邻居文件一致？有没有和本次已写或仓内已有重复的 helper？
错误路径处理与本模块惯例一致？暴露给后续块的接口签名此刻定稿？全部块（含扇出子 Agent 的产出）
完成后通读一遍完整改动，处理跨块漂移（同一概念两套写法、前紧后松的错误处理），然后才进入编译。
块与块之间不编译、不 done、不询问用户。

写码前先读 `.mae-flow-work/plugin-resources/standards/code-taste-v1.md`（编码基准）与
`standards/comment-standard-v1.md`（注释标准）；动笔前先找仓内同类实现，能复用的抽象不重造，
新文件的命名与结构顺应同目录邻居。基准是目标不是门禁，但 Craft Reviewer 与人工检视会按它挑刺。

实现完成后执行 `python "{MAEFLOW_PATH}" agent-task compile --scope "本需求完整代码增量"`，按任务卡启动
compile-agent。编译成功后执行 `done`。此时保持代码未提交，供用户统一检视。
如果任务卡已经启动但没有收到返回，先检查已记录的 Agent 生命周期；禁止自动重派或重复编译。
